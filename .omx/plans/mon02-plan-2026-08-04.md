# MON-02 Monitor Session Merge

## Objective

Close the ReadingSession/monitor boundary without making camera availability a
reading prerequisite. A completed monitor run must enrich the existing local
session, preserve its database identity and finalization fields, and leave the
session's empty monitor fields untouched when the service is unavailable.

## Scope

- `src/features/reader/ReaderPage.tsx`
- `src/db/sessions.ts`
- `src/stores/sessionStore.ts`
- `src/db/files.ts`
- `monitor/README.md`
- `scripts/probe-monitor-session.mjs`
- Graph/run-state evidence for `D4` and `MON-02`

## Contracts

- Camera inference remains local to `monitor/`; the browser only receives JSONL
  frames after a session stops.
- `ReadingSession.id`, `endedAt`, `durationSec`, and `linesRead` are owned by
  the IndexedDB session and must not be replaced by monitor conversion.
- Monitor failures, empty sessions, malformed frames, and unavailable API
  responses do not block reader exit and do not fabricate focus data.
- File-scoped monitor session IDs prevent a previous paper's frames from being
  attached to a new paper after a fast route change.
- Monitor runs shorter than five seconds are retained as reading sessions but
  excluded from focus/distraction aggregates; no frontmost claim is inferred
  when monitor frames do not carry browser visibility data.

## Review Disposition

- Late monitor completion now returns the transaction's latest `ReadingSession`
  and updates `sessionStore`; stale list loads are ignored and dashboard
  distraction edits use a transaction-local read/modify/write.
- `endSession` uses the same transaction shape, so finalization cannot overwrite
  monitor fields that completed concurrently.
- The short-session check compares raw monitor timestamps; a 4.5 second
  fragment is excluded even though the display duration rounds to 5 seconds.
- Hard purge cascades `sessions.by-file` in the existing file deletion
  transaction, while soft delete keeps sessions for restore/history.

Static verification passed. Browser PDF/EPUB interaction and Python monitor
runtime smoke remain blocked by the environment and are recorded in the Agent
Dependency Graph rather than treated as release evidence.
