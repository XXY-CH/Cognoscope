# AI-03 Execution Plan

## Task DAG

1. `DATA`: add additive `qaMessages` IndexedDB store and CRUD, include hard-delete and data-clear cleanup.
2. `ARCH`: extend `QaMessage` and `ResearchDigest` with backward-compatible structured fields; keep existing IDs/routes and Markdown export.
3. `EXEC`: load/save QA by file, serialize streaming writes, abort on cancel/file switch, guard stale responses, and pass persisted QA into digest.
4. `UX`: expose loading, empty, streaming, cancel, offline and error states with tokenized Apple Design feedback and 44px controls.
5. `VERIFY`: type/build/lint/diff checks plus static fixture probes for persistence/structure/cancellation contracts.

## Acceptance trace

- One file always maps to one QA message history; switching files loads the target history and never shows the previous file.
- User and assistant messages are written locally; streaming state is recoverable as `streaming`/`error` rather than silently lost.
- `runDigest` consumes meaningful annotations and persisted QA, returns structured sections plus the original Markdown export.
- Offline/missing-key/cancel/error paths leave files, annotations, bookmarks and prior artifacts readable.
- `autoCite` remains a prompt-level request constrained to available page/locator references; it cannot promote evidence verification.

## Verification gates

`npm run build`, `npm run lint`, `git diff --check`, IDB schema/static probe, offline and stale-file switch review, and available browser smoke checks. Browser runtime absence is recorded rather than converted to `done`.
