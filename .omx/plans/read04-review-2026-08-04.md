## Findings

### HIGH-1 — PDF exact text anchors are unreachable because the selector ignores the CSS module class

**Locations:**

- `src/features/reader/canvas/SelectionToolbar.tsx:94-96,124-142`
- `src/features/reader/canvas/PdfPage.tsx:144-148`
- `src/features/reader/canvas/PdfTextLayer.module.css:6` (related unchanged contract)

`buildPdfTextOffsetAnchor()` is only exact when `findPdfTextLayer()` returns the PDF text-layer root. The helper uses `element.closest('.textLayer')`, but `PdfPage` mounts `className={textStyles.textLayer}` from a CSS module. The production build confirms the emitted class is `._textLayer_1eni6_6`; there is no literal `textLayer` class token for `closest('.textLayer')` to match.

As a result, normal PDF selections produce `anchor: ''` in `SelectionToolbar.tsx:195`, so `PdfPageAnnotations` cannot replay the saved exact occurrence. It then uses the quoted-text fallback, which reintroduces the first-occurrence/duplicate-quote failure that HIGH-1 was intended to remove. The static probe checks that the helper exists but does not mount the CSS module, so it does not catch this regression.

**Required remediation:** Pass the actual CSS-module class into the helper, or add a stable data attribute to the text-layer root and query that attribute. Add a fixture or DOM-level test that proves a real selection resolves to `pdf-text-offset-v1:<start>:<end>`.

### HIGH-2 — Concurrent EPUB display promises can overwrite a newer request

**Locations:**

- `src/features/reader/canvas/EpubRenderer.tsx:321-341`
- `src/features/reader/canvas/EpubRenderer.tsx:534-549`
- `src/features/reader/canvas/EpubRenderer.tsx:551-606`

The conditional clear guards only protect state cleanup. `replayPendingLocator()` awaits `rendition.display()` and then clears the handoff, while the TOC jump and annotation jump effects each start another untracked `rendition.display()` promise. The annotation path unconditionally synchronizes and flashes the captured annotation at `:578-580`, and reports an error/toast at `:582-589`, even if `annotationJumpId` or the file has changed while the promise was pending.

If a user requests annotation A and then annotation B, or clicks a TOC entry while an annotation/matrix jump is still pending, the older promise can resolve later and move the rendition back to the older location or flash/report the stale annotation. This violates the reader source-return contract even though `clearAnnotationJumpIfCurrent()` does not erase B's state.

**Required remediation:** Add a per-render request generation/cancellation guard around every async EPUB display path. Verify the captured file and request identity immediately before all navigation side effects, highlight synchronization, focus/flash, error state, and toast. Prefer serializing or cancelling obsolete display requests where epub.js permits it.

### HIGH-3 — Matrix/evidence locator replay failures are cleared without a durable unavailable state

**Locations:**

- `src/features/reader/canvas/EpubRenderer.tsx:321-341`
- `src/features/reader/canvas/PdfRenderer.tsx:122-137`
- `src/features/reader/ReaderPage.tsx:76-93` (unchanged Reader integration path)

The new `annotationLocatorStates` state covers authored annotation jumps, but not the separate `pendingLocator` handoff used for matrix/evidence return. An invalid or drifted EPUB CFI is caught and silently discarded in `EpubRenderer.tsx:333-338`. The PDF path accepts the page and clears the handoff after `setCurrentPage()` without recording an invalid/out-of-range reason (`PdfRenderer.tsx:122-130`); the store clamps the page instead of exposing that the requested locator was not valid. The URL/evidence recovery path also clears missing/failed rows in `ReaderPage.tsx:84-93` without a reader-visible unresolved reason.

A user can therefore return from a matrix row, land on a default/clamped page, and have no durable explanation or retry path. This is distinct from the annotation-specific unavailable state and violates the graph/Phase-005 requirement that an unresolvable source locator remain visibly unresolved rather than silently becoming a successful-looking reader state.

**Required remediation:** Add a reader-level handoff result/status with the captured file/row identity and reason. Validate PDF page bounds and EPUB replay success before clearing. Surface the reason in the Reader/return context and retain the handoff as unresolved or retryable.

### MEDIUM-1 — Empty-href EPUB containers lose structural sibling boundaries

**Locations:**

- `src/utils/epubToc.ts:20-35`
- `src/features/reader/panels/TocPanel.tsx:42-75,101-113`
- `scripts/probe-read04.mjs:187-223`

`flattenEpubToc()` removes every empty-href container and retains only a numeric descendant level. `buildOutlineTree()` can synthesize missing numeric levels, but it infers parents from the previous visible entry and cannot preserve sibling branches separated by hidden containers. For example, `empty root -> visible child(level 1), empty sibling container -> visible leaf(level 2)` is reconstructed as `visible child -> visible leaf`, rather than two branches.

The current fixture verifies that levels 1/2/3 survive flattening, but it does not pass parent identity into tree construction or assert the rendered tree for hidden-container siblings.

**Required remediation:** Preserve structural placeholder nodes or parent paths through the EPUB projection, or build the tree from the original navigation hierarchy. Add a pure tree fixture for hidden-container siblings and arbitrary depth.

### MEDIUM-2 — EPUB tooltip/focus decoration treats `getContents()` as a single document

**Locations:**

- `src/features/reader/canvas/EpubRenderer.tsx:99-129`
- `src/features/reader/canvas/EpubRenderer.tsx:132-162`
- `src/features/reader/canvas/EpubRenderer.tsx:226-318`
- `node_modules/epubjs/src/rendition.js:986-992` (runtime API contract)

`rendition.getContents()` returns `Contents[]`, but `decorateEpubHighlight()` and `flashEpubHighlight()` treat the result as one `Contents` object and access `.document` directly. That throws and is silently swallowed, so the preview title/ARIA/focus metadata and the flash path do not run in the current runtime. The `markElement` fast path only sets title/ARIA and does not install the role, tabindex, or keyboard handler.

Even after iterating the returned contents, marks added for a non-current chapter also need decoration after epub.js attaches that view; the current code has no render/display hook for that lifecycle.

**Required remediation:** Iterate all returned `Contents`, then decorate every newly attached annotation mark from the rendition content/view lifecycle, or use a delegated handler/attribute step that runs after each displayed section. Add a visible non-animated focus style for reduced-motion users.

### MEDIUM-3 — EPUB active TOC matching ignores fragments

**Locations:**

- `src/features/reader/panels/TocPanel.tsx:177-188`
- `src/features/reader/panels/TocPanel.tsx:272-280`

`epubHrefMatches()` strips the fragment and falls back to path-only matching in the same `findIndex()` pass. When two entries target `chapter.xhtml#intro` and `chapter.xhtml#method`, a current `chapter.xhtml#method` location can match the first entry by path and mark the wrong TOC item active.

**Required remediation:** Prefer exact canonical href/fragment matching in a first pass, and use path-only matching only when no fragment-specific entry matches.

### MEDIUM-4 — New annotation styles bypass the token source of truth and dark-theme adaptation

**Locations:**

- `src/features/reader/canvas/PdfPageBookmarks.module.css:73-95`
- `src/features/reader/canvas/EpubRenderer.tsx:78-86`

The new PDF annotation classes introduce literal highlight colors, `2px` radii, and `-2px` inset values. The EPUB path separately hardcodes the same palette and fixed opacities for SVG marks. Repository policy requires component CSS sizing/color/duration/z-index values to use design tokens, and `UI_spec.md` requires light/dark parity with appropriate dark-mode adaptation. These additions bypass the token source of truth and keep the EPUB annotation palette unchanged in dark mode.

**Required remediation:** Add semantic annotation-color tokens (including dark-theme overrides and spacing/radius tokens where needed) and consume them consistently in PDF CSS and EPUB SVG style generation.

## Low-risk maintainability findings

### LOW-1 — Reader components now exceed the repository size target and combine unrelated state machines

**Locations:**

- `src/features/reader/canvas/EpubRenderer.tsx` — 718 lines
- `src/features/reader/panels/TocPanel.tsx` — 533 lines

The diff adds navigation, selection transport, TOC projection, annotation lifecycle, highlight decoration, and multiple async replay effects to already stateful components. Extracting a bounded `useEpubAnnotationHighlights`, `useEpubLocatorReplay`, or tree component would reduce regression risk without changing behavior.

### LOW-2 — Preview and palette logic is duplicated across PDF CSS, PDF replay, and EPUB runtime

**Locations:**

- `src/features/reader/canvas/EpubRenderer.tsx:69-86`
- `src/features/reader/canvas/PdfPageAnnotations.tsx:21-28`

The same preview truncation and annotation palette are maintained in multiple surfaces. This is not a current correctness blocker, but future changes can easily make PDF and EPUB tooltip length, colors, opacity, or theme behavior diverge.
