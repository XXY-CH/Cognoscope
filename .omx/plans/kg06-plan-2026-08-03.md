# KG-06 Source Invalidation Plan

## Objective

When a source file enters the recycle bin, preserve its records but revoke
citation-ready state across evidence rows, analysis items, research signals, and
research leads. Restoring the file may restore navigation, but it must not
silently restore verification.

## Ownership

- `src/db/sourceInvalidation.ts`: one transaction for FileNode soft-delete
  metadata and reconciliation of persisted dependent records.
- `src/stores/fileStore.ts`: invoke reconciliation after soft delete while
  preserving the existing graph removal and restore behavior.
- `src/utils/evidenceCitation.ts` and
  `src/utils/evidenceAnalysisCitation.ts`: reject unavailable source records at
  the final copy boundary.
- `scripts/probe-evidence-matrix.mjs`: static contract checks for source
  invalidation and citation gates.
- `docs/graph-engineering.json`, `docs/agent-run-state.json`, `PROGRESS.md`:
  checkpoint and evidence only.

## Invariants

1. Soft delete never removes evidence, signal, lead, or matrix records.
2. Any evidence item whose file is unavailable becomes `unresolved`; its row
   becomes `unresolved`.
3. Analysis items that reference an invalidated row become `unresolved`.
4. Signals and leads with a deleted source become `stale` and retain source IDs.
5. Restore only makes Reader navigation available again; the user must reverify.
6. Citation formatting requires active source files and verified rows/items.

## Hard-delete Boundary

The existing purge path remains an explicit irreversible cascade for a matrix
containing the purged file. KG-06 applies to recycle-bin soft delete; it does
not silently change purge semantics or pretend purged IDs remain recoverable.

## Verification

- Build and lint.
- Evidence probe checks the invalidation markers and copy gates.
- A source-invalidation fixture exercises soft-delete, restore, and citation
  eligibility without requiring a browser.
- Evidence-row, analysis, signal, and lead writes re-read current IndexedDB
  files/rows/signals inside their transactions; non-citation-ready row IDs are
  propagated so restoring a file cannot revive an old verified write. The
  static evidence probe records those guards and the bundled fixture covers the
  pure reconciliation contract. A browser-backed IndexedDB fixture is not
  available without adding a test dependency, so transaction execution remains
  part of the blocked browser/manual gate.
- Browser source deletion/restore remains pending while no Chromium runtime is
  available.
