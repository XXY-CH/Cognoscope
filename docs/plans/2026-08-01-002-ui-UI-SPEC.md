# Phase 002 — UI Design Contract

> Visual and interaction contract for the AppShell, library, knowledge graph,
> evidence matrix, and reader shared chrome. This phase follows Apple Design
> principles of purpose, agency, familiarity, flexibility, simplicity, craft,
> and delight while staying within the existing manual CSS token system.

## Scope and source decisions

- **In scope:** AppShell/sidebar/file directory, knowledge graph, evidence matrix,
  and reader shared chrome (top bar, bottom bar, canvas/panel relationship).
- **Out of scope:** dashboard visual redesign, new AI capabilities, graph edge
  authoring, cloud sync, and a component-library migration.
- **Existing authority:** `UI_spec.md` remains the product source of truth;
  `src/styles/tokens.css` is the implementation token source of truth.
- **Phase correction:** the 240px sidebar must never compress the primary content
  below the compact breakpoint. At widths below 900px it becomes an overlay drawer and contributes
  zero width to the AppShell layout.
- **Existing behavior to preserve:** local-first/offline operation, lucide icons,
  named exports, CSS Modules for feature components, plain CSS for layout shell,
  and the existing route/store contracts.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none; reuse `src/components/common` |
| Icon library | `lucide-react`, 1.5px stroke, 16/20/24px sizes |
| Font | `var(--font-sans)`: Inter, SF Pro Text, PingFang SC, Microsoft YaHei, system-ui |
| Styling | Existing CSS custom properties in `src/styles/tokens.css`; no new dependency |
| Material | Opaque token surfaces by default; translucent sheet chrome only when it improves hierarchy and contrast |

### Apple interaction principles for this phase

1. **Purpose:** keep the primary task visible: choose a paper, inspect a relation,
   verify evidence, or read. Secondary actions move into an overflow menu on
   narrow screens rather than competing for width.
2. **Agency:** every destructive action is reversible where possible; soft delete
   offers undo, and dialogs are reserved for permanent or high-cost actions.
3. **Familiarity:** navigation, back, close, search, overflow, and trash retain
   their conventional positions and lucide symbols across routes.
4. **Flexibility:** the same content adapts from pointer/keyboard desktop to
   touch-first mobile without hiding task-critical actions.
5. **Simplicity:** no decorative cards inside cards, no gradients, and no controls
   that merely explain the interface. Use hierarchy, whitespace, and direct labels.
6. **Craft:** all transitions use token values, focus is visible, text never clips
   into neighboring controls, and every fixed-format surface has a stable size.
7. **Delight:** feedback starts on pointer-down, meaningful actions confirm with a
   concise toast, and panel motion follows the direction of the triggering control.

## Spacing Scale

Use the existing 4px base scale. Values below are the phase's active aliases; use
the corresponding `--sp-*` tokens rather than hardcoded values.

| Token | Value | Existing token | Usage |
|-------|-------|----------------|-------|
| xs | 4px | `--sp-1` | icon gaps, focus offsets, hairline grouping |
| sm | 8px | `--sp-2` | compact controls, row/action gaps |
| md | 16px | `--sp-4` | default control padding, card internals, mobile page padding |
| lg | 24px | `--sp-6` | desktop page padding and section gaps |
| xl | 32px | `--sp-8` | major content separation and empty-state breathing room |
| 2xl | 48px | `--sp-12` | large empty states and reader canvas margins |
| 3xl | 64px | existing layout dimensions | reserved for fixed structural heights, not arbitrary gaps |

Exceptions:

- Interactive hit areas are **44x44px minimum on touch layouts** (`max-width:
  899px`) even when the visual icon is 20px. Use an existing 32px visual control
  inside a 44px hit target; do not enlarge the icon to fill the target.
- Desktop `IconButton` remains 32x32px to preserve the existing dense library and
  reader chrome. Keyboard focus outlines may extend outside the visual box.
- Desktop content padding stays 24px; mobile content padding is 16px, and at
  widths below 400px it is 12px only where a 16px inset would cause truncation.
- Gap values remain multiples of 4px. `--radius-*`, border, shadow, and z-index
  values continue to come from tokens and are not spacing substitutes.

## Typography

The phase chrome uses four active sizes and two weights. Existing dashboard-only
32px/700 display tokens remain unchanged but are not introduced into this phase.
Reader document text is content, not chrome, and retains its user-adjustable
`--text-reader` scale.

| Role | Size | Weight | Line Height | Token / use |
|------|------|--------|-------------|-------------|
| Body | 14px | 400 | 22px (1.57) | `--text-body`; file rows, evidence prose, graph details |
| Label / metadata | 12px | 400 | 18px (1.5) | `--text-xs`; timestamps, tags, locator/status metadata |
| Heading | 18px | 600 | 26px (1.44) | `--text-h2`; panel/section titles and mobile sheet titles |
| Page title | 24px | 600 | 32px (1.33) | `--text-h1`; PageHeader and primary route title |

Typography rules:

- Use `var(--font-sans)` for all chrome. Do not add a webfont or dependency.
- Reader file titles may use the existing 15px/600 `--text-h3` treatment when a
  24px title would crowd TopBar controls; this is a structural exception, not a
  new type tier.
- Keep `letter-spacing: 0` for UI labels and body. Do not use negative tracking.
- Use `font-variant-numeric: tabular-nums` for page counts, file sizes, evidence
  counts, and status numbers.
- Headings may wrap at mobile; never force an ellipsis when the full title is the
  user's only way to identify a file or matrix.
- Reader document text: 16px/1.75 by default, adjustable 14–24px through the
  existing reader settings; never scale it with viewport width.

## Color

Use the existing light/dark semantic tokens and `data-accent` variants. The
60/30/10 split is a compositional target, not a reason to introduce new colors.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg-base)` / `var(--bg-surface)` | App background, reader canvas, page headers, dialogs, form surfaces |
| Secondary (30%) | `var(--bg-elevated)` / `var(--bg-hover)` | Sidebar, graph canvas frame, evidence row frame, panel interiors, hover feedback |
| Accent (10%) | `var(--accent)` / `var(--accent-subtle)` | Reserved emphasis listed below; adapts to blue/green/yellow/pink preference |
| Destructive | `var(--danger)` | Permanent delete, empty trash, destructive menu items, error emphasis only |
| Warning | `var(--warning)` | Unresolved evidence, unavailable source, camera unavailable, non-fatal caution |
| Success | `var(--success)` | Local detection live state, saved/confirmed state, successful completion |

Accent reserved for:

- active route text/icon and its 3px navigation marker;
- selected file rows, selected graph nodes, focused/active evidence row, and the
  primary action in the current task;
- `:focus-visible` rings and keyboard-adjustable resizers;
- graph edge/node emphasis when a relation is selected;
- verified evidence status and source jump affordance;
- progress states that communicate the current operation (import, graph analysis,
  matrix extraction), never as ambient decoration.

Do not use accent for every link, every border, all icons, or large background
areas. Secondary text remains `--text-secondary`/`--text-tertiary`. Status must
never rely on color alone: pair it with text, icon, label, or line style.

Contrast requirements:

- primary text on dominant surfaces: at least 7:1;
- secondary text and large text: at least 4.5:1;
- non-text controls, focus indicators, graph nodes, and borders: at least 3:1;
- accent buttons use `var(--text-on-accent)` and must remain readable in every
  `data-accent` and dark-theme combination.

## Copywriting Contract

Copy is concise, specific, and action-oriented. Avoid generic labels such as
"确定" when the verb can identify the result.

| Element | Copy |
|---------|------|
| Library primary CTA | `导入文件` |
| Graph primary CTA | `打开阅读` when a file node is selected; otherwise no fake CTA |
| Evidence primary CTA | `生成证据矩阵` |
| Reader primary navigation action | `返回文件目录` |
| Library empty heading | `暂无文件` |
| Library empty body | `拖拽文件到此处，或点击导入` |
| Search empty heading | `无匹配结果` |
| Search empty body | `尝试修改关键词或检查是否在正确目录` |
| Graph empty heading | `暂无图谱数据` |
| Graph empty body | `导入并阅读论文后，Congnoscope会在本地整理论文与关键词关系` |
| Graph no-match | `无匹配节点` |
| Evidence empty heading | `还没有证据矩阵` |
| Evidence empty body | `选择 3–5 篇论文并提出比较问题，开始整理可核对的证据` |
| Reader canvas empty | `无法显示文档` / `请返回文件目录并重试` |
| Generic error | `加载失败。请重试；如果问题持续，请检查本地数据状态。` |
| Offline | `已离线，本地功能可正常使用` |
| AI unavailable | `离线状态下暂不可用` |
| Matrix unresolved | `待核对：尚未找到可回读的来源定位` |
| Matrix confirmed | `已确认` |
| Import success | `成功导入 N 个文件` |
| Rename success | `已重命名` |

Destructive confirmations:

- Move to trash: `将“{名称}”移入回收站？移入后仍可恢复。` Buttons: `移入回收站` / `取消`.
- Permanently delete: `永久删除“{名称}”后无法恢复，确认删除？` Buttons: `永久删除` / `取消`.
- Empty trash: `清空回收站后所有文件都无法恢复，确认清空？` Buttons: `清空回收站` / `取消`.
- Delete a saved matrix, if exposed by the route: `删除这个证据矩阵？已保存的行和审核状态将一并移除。` Buttons: `删除矩阵` / `取消`.

Undo rule: soft-delete toasts include `撤销` for 5 seconds; permanent actions
never offer a misleading undo.

### Shared control geometry

- Button heights remain 32/36/40px (`sm`/`md`/`lg`) on pointer layouts.
- Inputs remain 36px high, with 2px accent focus glow from existing tokens.
- Touch controls use 44px minimum hit area with 8px visual spacing.
- Menus are at least 180px wide on desktop and at least 240px when the menu is
  the only way to access a mobile row action; menu items are 44px high on touch.
- Dialogs use existing 440px confirmation / 600px form widths with
  `max-width: calc(100vw - 32px)`; mobile dialogs are bottom sheets only when
  the action has a long form, otherwise centered and full-width within the inset.
- Keep border radius at existing 4/8/12/16px tokens; do not introduce pill cards.

## Layout and Responsive Contract

### Desktop shell (>=1200px)

- Sidebar is 240px expanded or 64px collapsed; its state persists through the
  existing `uiStore`.
- Main region has `min-width: 0`; only the content region scrolls vertically.
- PageHeader remains 56px sticky with 24px horizontal padding.
- File table has the existing flexible name column and fixed metadata columns.
- Graph uses a two-pane canvas with a bounded inspector; evidence content is
  centered at the existing digest width; reader may show TOC and side panel.

### Tablet (900–1199px)

- Sidebar defaults to 64px collapsed; it still participates in layout.
- Graph panes remain available but may stack at 900px according to content height.
- Reader TOC and SidePanel become non-blocking overlays rather than reducing the
  canvas below its usable width. Each overlay originates from its trigger edge.
- Header actions may wrap once; never let action text overlap the title.

### Compact (600–899px)

- Sidebar becomes a top-level left drawer. Closed state contributes zero layout
  width. Open state: `width: min(280px, calc(100vw - 48px))`, full viewport height,
  scrim `var(--overlay-drawer)`, focus trap, Escape/outside-click close, and return
  focus to the menu trigger.
- A persistent 44px menu trigger is present in the PageHeader; it is the only
  replacement for the removed sidebar width.
- File list hides last-read and size columns, keeping filename, updated time, and
  overflow actions. Toolbar controls wrap into two rows without horizontal scroll.
- Graph canvas and inspector stack; inspector appears after the canvas and can
  scroll independently within `--graph-inspector-max-height-mobile`.
- Evidence matrix toolbar actions wrap; source metadata and action controls may
  occupy separate rows.
- Reader canvas remains the dominant region; TOC/SidePanel are edge sheets with
  a visible close button and no simultaneous two-panel squeeze.

### Mobile target (390x844 and all widths <600px)

- **No 240px sidebar in normal flow.** `.app-shell__main` is 100vw wide and the
  sidebar is fixed/overlay only. `overflow-x: hidden` is required at shell and
- PageHeader uses 56px height, 12–16px horizontal padding, a 44px menu button,
  title at 18px/26px when actions are present, and an overflow menu for secondary
  actions. The title may wrap to two lines only when there is no action row.
- File directory switches from `<table>` presentation to card rows: filename and
  type on the first line, updated time/size on the second, and a 44px overflow
  trigger on the trailing edge. Selection remains explicit and visible; do not
  rely on hover.
- Batch action bar becomes a two-row sticky region: count on the first line,
  actions on the second, with 44px controls and no clipped labels.
- Knowledge graph uses one full-width canvas viewport followed by an inspector
  block/sheet. Show the hint `建议在更大屏幕查看` only as supporting text; graph
  remains usable for search, selection, and opening a paper.
- Evidence rows use one column: conclusion, provenance/status, excerpt, note,
  and actions in that order. `回读来源` and `复制引用` remain visible buttons,
  not icon-only controls.
- Reader hides both panels from the persistent layout. TOC and SidePanel open as
  full-height sheets (`max-width: 100vw`) with a solid/translucent surface and a
  scrim. ReaderCanvas `min-width` becomes 0 at this breakpoint; document width
  is `min(100%, 720px)` with 12px outer padding.
- Reader TopBar keeps back, file identity, and one menu affordance. Reader
  BottomBar wraps into two rows if needed; page navigation and `已读 N 行` stay
  visible, while secondary zoom controls move to the overflow menu.
- Minimum safe area: add `env(safe-area-inset-top)`/`bottom` to fixed reader
  chrome when supported, without changing content semantics.

### Touch and hover parity

- At `@media (hover: none)`, row actions are always available through a visible
  overflow button. Hover-only replacement of timestamps is never the only path.
- Pointer-down gives immediate `--bg-active`/opacity feedback; commit occurs on
  pointer-up/click. A cancelled touch must restore the previous state.
- Dragging a graph node or panel resizer tracks the pointer 1:1 using Pointer
  Events and pointer capture. On release, settle with a critically damped motion;
  do not snap from a stale target value.

## Route-specific visual and interaction contracts

### AppShell, Sidebar, and PageHeader

- Sidebar visual hierarchy is `--bg-elevated` + one subtle divider; no gradient or
  decorative shadow in normal desktop flow.
- Active nav has `--bg-active`, accent icon/text, and the 3px left marker. The
  selected state remains visible in collapsed and mobile drawer modes.
- Mobile drawer enters from the left and exits along the same path. The scrim is
  dismissible, but the drawer must also have a labelled close control.
- PageHeader title answers “where am I”; actions answer “what can I do here”.
  Route-level actions must not be duplicated in Sidebar.
- Settings and dialogs use the existing focus trap hook; Escape closes the
  topmost transient layer in order: tooltip, menu, drawer, dialog.

### File directory

- Search input is full-width on mobile and retains `搜索文件名…` placeholder.
- Import dropzone uses a 160px desktop height, but on mobile becomes a 120px
  tappable target and keeps the same file limits (PDF/EPUB/Markdown/TXT, 20 files,
  200MB each).
- Loading: six row skeletons on desktop/tablet; six stacked card skeletons mobile.
- Empty: use the exact library empty copy above and show `导入文件`.
- Error: inline alert with warning icon, concrete reason, and `重试` button; do
  not replace the whole route with a blank screen.
- Selection: selected rows/cards use `--bg-active`; count is announced through the
  existing status/toast mechanism. Batch delete remains soft delete with undo.
- Sorting stays available through labelled controls; on mobile it moves into the
  toolbar overflow menu and announces the current order.

### Knowledge graph

- The graph is a work surface, not a decorative hero. Canvas consumes available
  height and keeps controls in a compact toolbar at the top.
- Nodes retain existing semantics: 40px file, 32px keyword/tag, 56px folder;
  labels are at most two lines with an accessible full label.
- Hover enlarges a node only 1.1x; selected state is an accent ring and not a
  color-only signal. Related edge emphasis is paired with selected-node text in
  the inspector.
- Graph analysis progress uses a 32px `--bg-active` status strip and text such as
  `正在整理论文关系…`; it disappears after completion and does not block search.
- Loading: graph-area skeleton/neutral canvas; empty: `暂无图谱数据`; error:
  `图谱加载失败。请重试。` + `重试`.
- No manual create/delete edge affordance. Node menus may open, focus related
  nodes, hide a node, or open the source paper only.
- Inspector remains readable at narrow widths; relation lists use buttons with
  full titles and an explicit `打开阅读` action where a file exists.

### Evidence matrix

- Setup surface clearly separates selected papers, `comparisonQuestion`, and the
  `生成证据矩阵` action. Selection is constrained to 3–5 papers and shows the
  current count before generation.
- Every row displays conclusion, source identity, locator kind, excerpt, and
  verification status without requiring a hover. AI proposals are never styled as
  confirmed facts.
- Status contract:
  - `待核对`: neutral/warning treatment and `回读来源` or correction action;
  - `争议`: warning treatment with the disagreement visible;
  - `已确认`: success treatment plus a visible source path;
  - `证据不足`: warning treatment; never allow it to be copied as verified.
- Loading/extracting: show row skeletons and `正在整理证据…`; cancellation or
  stale responses restore the last stable matrix and show no false success.
- Offline saved matrices remain editable. New AI extraction is disabled with
  `离线状态下暂不可用`; do not hide existing evidence.
- Copy action uses `复制引用` and includes conclusion, source, locator, excerpt,
  and optional annotation context. Confirmation is a success toast, not a modal.
- Research analysis is secondary to the matrix: it appears after confirmed rows,
  labels each draft as a proposal, and lists row references before allowing copy.

### Reader shared chrome

- TopBar is a stable 48px desktop / 48px mobile surface with back, file identity,
  mode controls, and essential status. Use a compact menu at mobile rather than
  shrinking the file title below readable size.
- BottomBar keeps page navigation, progress, zoom/page controls, `已读 N 行`, and
  the camera status indicator. Camera state always includes a dot plus text and
  the privacy behavior remains local-only.
- ReaderCanvas has `min-width: 0` below 600px and receives the largest available
  width. It must not be forced to 480px when a side sheet is open.
- TOC and SidePanel transitions originate from their trigger edge, use transform
  and opacity only, and can be closed/reopened during motion. On desktop they may
  use width transitions; on mobile they use sheet transforms.
- SelectionToolbar is anchored to the selection and clamped to the viewport. It
  must not cover the selected text or extend beyond a 390px viewport.
- Loading: renderer placeholder/skeleton; error: inline `无法显示文档` with
  `返回文件目录` and `重试`; empty/unsupported format remains explicit.
- Offline reading, annotations, bookmarks, and local camera status remain fully
  usable. AI controls are disabled only where the existing offline policy says so.

## State Matrix

Every data region implements all four baseline states; no route may render only a
success path.

| Surface | Loading | Empty | Error | Success / interaction states |
|---------|---------|-------|-------|------------------------------|
| AppShell | route fallback skeleton | n/a | route error region with retry | online/offline, light/dark, expanded/collapsed, mobile drawer open/closed |
| File directory | 6 row/card skeletons | `暂无文件` / search no-match | inline reason + `重试` | hover/focus/touch actions, selected, sorting, importing, undo toast |
| Graph | neutral canvas skeleton | `暂无图谱数据` | graph error + retry | analysis progress, node hover/selected, filtered/no-match, inspector open |
| Evidence | row skeletons + extraction status | `还没有证据矩阵` | extraction/persistence error + retry | proposed, unresolved, disputed, confirmed, stale/cancelled, offline editable |
| Reader chrome/canvas | renderer placeholder | `无法显示文档` if no renderable content | document error + retry/back | panel open/closed, find open, selection toolbar, camera live/paused/denied/unavailable |

Async state rules:

- Disable only the action currently committing; keep navigation and cancellation
  available. Do not freeze the whole page during import, graph analysis, or matrix
  extraction.
- Use `role="status"`/`aria-live="polite"` for completion and progress; use
  `role="alert"` for destructive/error outcomes.
- Preserve the last stable content during refresh where possible; avoid a blank
  flash between loading and success.

## Motion, Materials, and Reduced Motion

- Use existing `--dur-fast: 120ms`, `--dur-base: 200ms`, `--dur-slow: 320ms` and
  `--ease-standard`/`--ease-out`/`--ease-in`. Do not add arbitrary durations.
- Hover, focus, press, icon swaps, and color changes use 120ms. Panel/drawer
  entry uses 200ms. Sidebar collapse and graph layout changes use 320ms only when
  they are not direct manipulation.
- Animate only `transform` and `opacity` for drawers, sheets, selection tools,
  and node hover. Width may transition for the desktop sidebar/panels, but pointer
  dragging must disable the transition during the drag.
- Mobile sidebar and reader sheets materialize from the triggering edge with a
  solid `--bg-surface` layer, optional `backdrop-filter` only when text contrast
  remains compliant, and a dimming scrim for modal focus. Never stack multiple
  translucent layers over text.
- Dragging/resizing must be interruptible. Track pointer capture, update 1:1, and
  settle from the current presentation value; do not wait for a previous transition.
- `prefers-reduced-motion: reduce`: remove slides, scale, graph layout animation,
  camera breathing, and skeleton shimmer; retain immediate color/opacity feedback
  and a <=100ms cross-fade where it improves comprehension.
- `prefers-reduced-transparency: reduce`: remove blur and use opaque surfaces.
- `prefers-contrast: more`: increase surface opacity and use a defined contrasting
  border; do not depend on shadow alone.

## Accessibility Contract

- Use semantic `<nav>`, `<main>`, `<header>`, `<table>`/`<th scope="col">`, and
  labelled `role="region"` panels. Every interactive component has an
  `aria-label` or visible accessible name.
- All controls are keyboard reachable in visual order. `:focus-visible` is a 2px
  accent outline with 2px offset from the existing tokens.
- Drawer/dialog open moves focus into the surface, traps focus while modal, and
  restores focus to the trigger on close. Escape closes the topmost surface.
- Sidebar collapsed labels, graph node full names, icon-only controls, and mobile
  overflow actions expose tooltips/accessible names; tooltip is never the only
  keyboard label.
- Hover row actions have focus-within and touch-menu equivalents. A keyboard user
  can rename, move, delete, open, and select without a pointer.
- Graph has a labelled canvas plus a text/list representation of selected node and
  relations. Provide a `查看数据`/accessible relation list path if the canvas
  cannot be interpreted by assistive technology.
- Evidence status is conveyed by text and icon, not color alone. Source links
  identify the file and locator; unresolved evidence explains why it cannot be
  opened.
- Reader camera status is continuously visible and includes the local-only privacy
  message in settings. Focus never disappears into a canvas or iframe.
- Text must wrap at 390px. No clipped headings, buttons, badges, or dialog copy;
  test with browser text zoom at 200% where practical.
