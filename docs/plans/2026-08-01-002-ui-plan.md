# Phase 002 - UI Refresh

## Goal

Make the shared Xuesen shell and its highest-frequency research surfaces usable
at mobile widths without changing the local-first data, routing, or AI contracts.
The first acceptance target is `390x844`, where the current 240px sidebar
compresses the application into an unusable narrow column.

## Scope

- Convert the sidebar to a left overlay drawer below 900px, with a visible menu
  trigger, close/escape behavior, focus return, and no layout width contribution.
- Let PageHeader titles and route actions wrap without clipping or overlap.
- Make the file toolbar use a full-width search row and a wrapping action row;
  preserve every existing action and label.
- Add token-only compact layout rules for the shell and file directory.
- Verify the knowledge graph, evidence matrix, dashboard, and library routes in
  the Codex in-app browser at mobile, tablet, and desktop viewports.

## Non-goals

- No new dependencies or component-library migration.
- No changes to IndexedDB, Zustand domain contracts, AI prompts, or routes.
- No dashboard content redesign in this phase.

## Implementation units

### UI-1 Shared shell and mobile navigation

Files: `src/components/layout/AppShell.tsx`, `Sidebar.tsx`, `Sidebar.css`,
`PageHeader.tsx`, `PageHeader.css`, `AppShell.css`.

Add a local mobile drawer state in AppShell. The sidebar remains in desktop flow,
but becomes a fixed left sheet below 900px; its scrim is dismissible and its
links close the sheet. PageHeader owns the mobile menu affordance so every shell
route has consistent wayfinding. Use the existing focus-trap hook and tokenized
motion; preserve desktop collapsed behavior.

### UI-2 File directory compact toolbar

Files: `src/features/file-directory/FileToolbar.module.css`,
`src/features/file-directory/FileDirectoryPage.module.css`,
`src/features/file-directory/FileTable.module.css`,
`src/components/common/IconButton.module.css`.

At compact widths, the search input occupies its own row, type filtering and
icon actions wrap, and the import action remains visible on a separate full-width
row. Prevent table content from forcing horizontal overflow and keep selected
rows/actions reachable by keyboard and touch.

### UI-3 Cross-route responsive polish

Files: route-specific CSS modules as needed after browser inspection.

Adjust only confirmed overflow, clipping, or overlap defects in graph/evidence/
reader surfaces. Preserve their existing visual language and data behavior.

## Verification gates

1. `npm run build`
2. `npm run lint` (no new diagnostics)
3. `git diff --check`
4. `node scripts/probe-evidence-matrix.mjs`
5. Codex in-app browser screenshots and DOM checks at `390x844`, `768x1024`, and
   `1280x800` for `/`, `/dashboard`, `/knowledge-graph`, and `/evidence-matrix`.
6. At 390px: no horizontal scrollbar, menu opens/closes, header actions fit,
   and the evidence/graph empty states do not clip.

## Risks and rollback

- The persisted sidebar preference may be collapsed from a desktop session. The
  mobile drawer explicitly renders expanded labels while open, so mobile remains
  understandable without changing the stored preference.
- The shell CSS is shared by every AppShell route. If a route-specific overflow
  appears, constrain that route root rather than widening the global shell.
- Changes are isolated to layout/CSS and can be reverted independently without
  touching evidence persistence or reader data.
