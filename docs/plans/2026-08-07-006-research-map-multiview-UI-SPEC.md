# Phase 006 - 多视图研究地图与论证呈现契约

> 本文把“图谱如何解释学术关系”落成可实现的产品与 UI 契约。
> Phase 005 仍是研究边界和证据权威；本文只细化图谱、矩阵和判断演化
> 如何共享一份事实数据并分别呈现。早期关键词访谈的双画布保留为资料
> 发现能力，不再作为全局研究推理的主界面。

## 1. 核心决策

Congnoscope不再把“所有论文之间的线”当成一个需要不断增强的单一图谱，而是把
“研究地图”定义为一套由同一份证据关系数据生成的视图：

```text
研究问题 / 范围
  -> 研究主张
     -> 支持、反驳、条件、局限、研究空白
        -> 可回读证据锚点
           -> 论文、页码、段落、核验状态
```

页面仍只有一个一级导航项“图谱”，内部使用任务型视图切换：

| 视图 | 默认问题 | 是否允许全局关系线 | 主要权威 |
|---|---|---:|---|
| `资料` | 我的研究材料如何分布？ | 仅结构/主题线索 | 文件与概念元数据 |
| `论证` | 这条主张由什么支持或限制？ | 只显示有类型的局部关系 | 证据矩阵与证据锚点 |
| `比较` | 不同论文究竟哪里相同或不同？ | 不画全局线 | 证据矩阵 |
| `演化` | 我的判断因什么证据发生变化？ | 用时间连接代替空间连线 | 判断版本与来源 |
| `探索` | 当前节点附近还有什么线索？ | 仅选中节点一到两跳 | 图谱候选关系 |

`论证` 是有研究问题时的默认视图；没有研究问题时默认进入 `资料`。
`比较` 不复制证据矩阵编辑器，而是展示摘要并提供“打开证据工作台”。
`探索` 是保留 Obsidian 式排斥/吸引的局部工具，不承担引用或结论职责。

## 2. 产品边界

### 2.1 三种事实等级

| 等级 | 内容 | 可以做什么 | 不可以做什么 |
|---|---|---|---|
| 导航线索 | 关键词共现、AI 语义候选、文件夹归属 | 找材料、缩小范围、打开阅读 | 证明主张、复制引用 |
| 待核对关系 | 已指向矩阵行或候选证据，但未完成核验 | 展示待办、进入证据工作台 | 标记为已确认 |
| 已核验证据 | 有原文摘录、稳定 locator、用户确认 | 支持论证、成果输出、复制引用 | 在来源失效后继续保持有效 |

图谱的空间距离、边粗细和相似度只代表“导航优先级”，不能被解释为证据
强度、因果概率或论文质量分数。所有关系必须同时显示文字状态和来源类型。

### 2.2 早期双画布的重新定位

原访谈要求论文图与关键词图并列。该决定解决的是“如何生成和浏览关键词”，
没有解决“论文到底支持什么”。因此：

- 论文/关键词并列能力迁移到 `资料` 视图的分层簇与概念展开。
- 不再默认让两个同等大小的力导向画布竞争注意力。
- 选中概念时，在检查器显示贡献论文和可回读证据；需要探索时才打开局部
  关系图。

## 3. 统一数据合同（设计层）

本阶段先定义投影所需的最小语义，不要求立即替换现有 IndexedDB 记录。
现有 `GraphNode`、`GraphEdge`、`KeywordNode` 和 `KeywordEdge` 通过适配器进入
下列投影；旧记录缺少字段时必须明确显示 `来源未记录`，不能补写成 AI 事实。

### 3.1 核心对象

```ts
type ResearchRelationType =
  | 'contains'
  | 'mentions'
  | 'relates'
  | 'supports'
  | 'contradicts'
  | 'qualifies'
  | 'extends'
  | 'uses_method'
  | 'uses_dataset'
  | 'measures';

type ResearchRelationStatus =
  | 'clue'
  | 'review'
  | 'verified'
  | 'disputed'
  | 'stale';

interface ResearchRelationProjection {
  id: string;
  type: ResearchRelationType;
  sourceRef: { kind: 'scope' | 'paper' | 'concept' | 'claim' | 'evidence'; id: string };
  targetRef: { kind: 'scope' | 'paper' | 'concept' | 'claim' | 'evidence'; id: string };
  reason: string;
  origin: 'user' | 'rule' | 'ai' | 'mixed' | 'unknown';
  status: ResearchRelationStatus;
  evidenceAnchorIds: string[];
  evidenceRowIds: string[];
  conditionIds: string[];
  navigationWeight?: number;
}
```

`evidenceAnchorIds` 只引用 `Annotation`/`EvidenceItem`，不复制摘录文本；
`evidenceRowIds` 只引用矩阵行；`navigationWeight` 不得在 UI 中标记为概率、
置信度或证据强度。

### 3.2 关系语义

| 类型 | 图上显示 | 最低要求 |
|---|---|---|
| `contains` | 所属 | 文件夹或研究范围结构 |
| `mentions` | 提及 | 原文关键词或稳定元数据 |
| `relates` | 相关线索 | 共现或 AI 候选，默认 `clue` |
| `supports` | 支持 | 定位摘录 + 主张/矩阵行 |
| `contradicts` | 反驳/存在矛盾 | 两侧均有可回读材料，不能由相似度单独生成 |
| `qualifies` | 条件化 | 条件文本与来源定位 |
| `extends` | 延伸 | 明确比较语境与来源定位 |
| `uses_method` / `uses_dataset` / `measures` | 方法/数据/指标 | 元数据或原文依据，显示为结构关系 |

首个实现只需把旧边映射为 `relates`、`mentions` 或 `unknown`，并把论证关系
先从已存在的证据矩阵与批注中投影出来。不要新增独立的“AI 推断事实层”。

## 4. 页面呈现

### 4.1 统一工作区骨架

桌面端保持一个主要阅读表面，采用 `208px minmax(0, 1fr) 320px`：

```text
┌──────────────────────────────────────────────────────────────┐
│ 图谱  当前研究问题                         视图  搜索  筛选 │
├──────────────┬───────────────────────────────┬───────────────┤
│ 范围导引栏    │ 当前视图                        │ 关系检查器     │
│              │                                 │               │
│ 研究问题      │ 节点/主张/矩阵/时间线            │ 为什么相连     │
│ 文件夹        │ 状态条与空状态                   │ 来源与核验     │
│ 论文簇        │                                  │ 回读与动作     │
│ 视图筛选      │                                  │               │
└──────────────┴───────────────────────────────┴───────────────┘
```

范围导引栏可收起；检查器内部滚动，不能把页面高度推大。顶部视图使用分段
控制，不增加新的一级导航。所有图标按钮提供 `aria-label` 和 tooltip。

### 4.2 `资料`：分层研究地图

默认用稳定的“线路”布局，不让节点随机漂移：

```text
研究范围
  ├─ 主题簇 A ─┬─ 论文 01 ── 方法 / 数据集
  │            └─ 论文 02 ── 方法 / 数据集
  └─ 主题簇 B ─── 论文 03 ── 结果指标
```

- 主题簇和文件夹可折叠；论文节点是主要可操作对象。
- 主题与论文之间的线只表达“提及/归属/相关线索”，选中后才显示原因。
- 超过 80 个可见节点时先显示簇，使用“展开此簇”进入局部视图。
- 关键词共现与 AI 语义关系显示为不同线型/图例，不使用发光或持续动画。

### 4.3 `论证`：主张中心的证据地图

这是解释学术关系的主视图。布局为从左到右的四条固定泳道：

```text
研究主张        支持 / 反驳 / 条件 / 局限        证据锚点        来源
┌────────┐      ┌──────────┐                   ┌──────┐      ┌──────┐
│ 主张 A │ ───▶ │ 支持     │ ───────────────▶  │摘录 1│ ───▶ │p.04  │
└────────┘      │ 条件     │                   └──────┘      └──────┘
                │ 反驳     │                   ┌──────┐      ┌──────┐
                └──────────┘ ───────────────▶  │摘录 2│ ───▶ │p.11  │
```

- 默认只显示当前研究问题下的 3-10 条主张；其余折叠为“更多主张”。
- `supports`、`contradicts`、`qualifies`、`extends` 必须有文字标签。
- 未绑定证据的关系显示为虚线 `线索`，不进入可引用输出。
- 证据摘录不是全局力导向节点，而是选中主张后的局部列表，目标上限 20 条。
- 选中关系时，检查器第一行直接回答“这是什么关系”，第二行回答“为什么”，
  第三行给出“回到哪篇论文的哪一页”。

### 4.4 `比较`：矩阵摘要，而不是第二张图

中间区域显示固定主张列和论文列：

```text
主张 / 条件              论文 01       论文 02       论文 03
────────────────────────────────────────────────────────────
提升长序列建模           支持 · p.4    条件 · p.8    未涉及
对低资源数据有效         反驳 · p.11   支持 · p.3    待核对
```

- 单元格同时显示关系类型、来源状态和 locator 摘要。
- 颜色只作辅助；文字、图标和焦点状态必须独立传达语义。
- 点击“打开证据工作台”进入现有矩阵编辑器，不在图谱页复制编辑逻辑。

### 4.5 `演化`：研究判断时间线

不使用 Git/commit 视觉，而使用研究状态：

```text
草案 ──有证据── 条件化 ──出现反例── 当前判断 ──待审视
  │                 │             │
  p.2               p.8           p.11
```

每个节点显示判断文本、变化条件、触发论文和核验状态；点击事件回到证据或原文。

### 4.6 `探索`：局部 Obsidian 模式

- 仅对选中的论文、概念或主张展示一到两跳邻域。
- 允许拖拽、排斥、吸引和缩放，但退出视图不改变事实数据。
- 节点数目标不超过 30，超出部分折叠为列表。
- AI 关系永远显示为 `AI 提议 / 线索`，不能通过物理距离升格为已确认。

## 5. 检查器合同

检查器顺序固定为：

1. 身份：名称、类型、研究范围、关联数量；
2. 关系解释：类型、方向、来源、理由、证据状态；
3. 来源预览：摘要或元数据，不冒充原文摘录；
4. 证据锚点：摘录、页码/CFI、匹配方式、核验状态；
5. 动作：`打开阅读`、`回读来源`、`查看证据`、`加入证据矩阵`。

没有可解析 locator 时，`回读来源` 和复制引用均禁用，并明确显示原因。

## 6. 交互与 Apple Design 约束

- 视图切换使用分段控制；范围导引栏和检查器使用可中断的滑入/滑出。
- 节点拖拽采用 Pointer Events + pointer capture，落点保留；重新布局从当前
  展示位置开始，不把节点瞬移回逻辑初始位置。
- 普通打开/关闭使用无弹性的短过渡；只有用户拖拽释放时才可交接速度和轻微
  回弹。`prefers-reduced-motion: reduce` 下改为即时布局或短淡入。
- 半透明材料只用于顶栏、导引栏和非阻塞检查器；不叠加多层半透明卡片。
- 不使用渐变球、发光连线、持续漂移、无来源百分比或装饰性粒子。
- 主标题与研究问题采用系统字体；证据摘录保持舒适行距，工具面板使用紧凑
  信息密度。字距不通过全局负值解决。

## 7. 响应式合同

| 宽度 | 呈现 |
|---|---|
| `>=1200px` | 导引栏 / 主视图 / 检查器三表面并列 |
| `768-1199px` | 导引栏变为顶部选择器，检查器可覆盖展开 |
| `<768px` | 主视图先呈现；关系与证据改为底部 Sheet 或层级列表 |

移动端不得通过缩小字体容纳桌面图。所有超出列表在内部滚动；页面不产生横向
溢出。画布必须有列表化可访问替代路径。

## 8. 验收标准

### 产品

- 用户能明确区分“资料关联”“论证关系”和“可引用证据”。
- 从任意已显示关系都能看到关系类型、理由、来源和核验状态。
- 只有定位可回读且已核验的证据能进入成果中心的可引用材料。
- 论文数量增加时，系统先折叠为簇或局部视图，不把整张图压缩成不可读的线团。

### 工程

- 旧图谱记录仍可读取；缺失字段显示 `来源未记录`。
- 图谱投影不复制 `Annotation`、`EvidenceItem` 或矩阵文本，只保存稳定 ID 引用。
- 图谱关系失败不阻断论文入图；证据来源失效会降级关系和引用状态。
- 视图筛选、选中节点、阅读回读和矩阵入口保留现有稳定 ID/路由合同。

### QA

- `npm run build`、`npm run lint`、`git diff --check`；
- 纯投影测试覆盖关系类型、节点上限、旧记录降级和证据状态；
- 390/768/1280 视口覆盖视图切换、检查器关闭/回焦点、无横向溢出；
- 键盘、主题、离线、来源失效和 `prefers-reduced-motion` 有独立证据；
- 浏览器运行时不可用时，`AG-QA.browser` 保持 `blocked`，不以静态探针冒充通过；本轮 Codex 浏览器门、KG-06 删除/恢复交易和 P4 矩阵来源门已通过，MON-02 摄像头运行时仍需独立验收。

## 9. 明确不做

- 不再扩大全局 Obsidian 式力导图的节点数量；
- 不把 AI 相似度或共现权重称为证据强度；
- 不在图谱页复制矩阵编辑器或成果写作编辑器；
- 不从标题相似度推断真实引用关系；
- 不新增 UI 框架、动画依赖或第二份证据事实源。

## 10. 后续决策点

1. `concept` 是否持久化拆分为主题、方法、数据集、结果指标；
2. 引用脉络是否接入 OpenAlex/Crossref 等可验证书目信息；
3. 关系确认是否继续只由证据矩阵核验触发；本阶段默认保持单一核验入口。
